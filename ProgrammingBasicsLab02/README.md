## 1. Призначення програми
Програма реалізує обробку даних для оцінювання результатів навчання студентів за двома показниками: балами за самостійну роботу `independent` та балами за опитування `quiz` 

Обробка здійснюється послідовно без збереження історії записів у масивах. Програма обробляє $N$ ($1 \le N \le 30$) 
Для кожного обчислює підсумковий бал $m$, визначає категорію та перевіряє умову пошуку, акумулюючи підсумкову статистику в пам'яті.

---

## 2. Вхідні дані, формула та класифікація

### Вхідні поля та допустимі межі
- `independent`: бали за самостійну роботу, межі `[0..40]`
- `quiz`: бали за опитування, межі `[0..60]`

### Показник
- **Формула:** $m = \text{independent} + \text{quiz}$ `(діапазон $0..100$)`

### Класифікація результату (`categoryFor`)
1. Якщо `independent < 20` $\rightarrow$ `"потрібно посилити самостійну роботу"`
2. Інакше, якщо $m < 50$ $\rightarrow$ `"підсумок нижче порога"`
3. Інакше, якщо $m \le 79$ $\rightarrow$ `"стабільний результат"`
4. Інакше $\rightarrow$ `"високий результат"`

### Умова пошуку `isSearchMatch` $\rightarrow$ `independent >= 20 && m >= 50`

## 3. Перевірки `assert`
У програмі реалізовано автоматичні перевірки логіки до початку циклу обробки:

## Дефект D4

- **Назва:** Підрахунок кратних до включної верхньої межі.
- **Суть дефекту:** У вихідній функції `countMultiples` використовувалася умова циклу `value < limit`, через що верхня межа (`limit`) не перевірялася.
- **Виправлення:** Умову циклу змінено з `value < limit` на `value <= limit`.
- **Відтворення:** Протестовано у Visual Studio Debugger (breakpoint, F5, F10/F11, вікно
- **Перевірено:** контрольний приклад `limit=6, divisor=3` $\rightarrow$ результат `2`.
